# Plan 01 — Drift assertion + TTS config UI cleanup

## What landed

**editor-store.ts (loadFromStepState)**: After the sync `set({...})`,
schedules a 1500ms `setTimeout` that re-reads state and computes
`abs(sum(scene durations / fps) - last(subtitles).endFrame / fps)`.
If the gap exceeds 0.5s, logs a `console.warn` with both numbers
and the drift. The 1500ms delay covers the SRT fetch promise that
runs asynchronously inside the same function.

**reels/page.tsx (ConfigPanel)**:
- Default `ttsSpeed` fallback bumped from `1.1` → `1.35` to match
  the backend default (was stale by ~6 commits).
- Default `ttsVoice` fallback changed from `"nova"` → `"Charon"` to
  match the backend default.
- Slider range expanded: `min=0.8 max=1.6 step=0.05` (was
  `0.8..1.5 step=0.1`).
- Voice list rewritten from stale OpenAI options (nova/shimmer/alloy/
  echo/fable/onyx) to actual Gemini voices the backend uses
  (Charon/Puck/Kore/Fenrir/Aoede/Leda/Orus/Zephyr).
- Label changed from "Voz TTS" → "Voz TTS (Gemini)" to make the
  provider explicit.

## How it satisfies the must-haves

- Drift smoke-alarm fires when sum-of-scenes ≠ last subtitle end (D-04)
- TTS speed slider matches backend default and exposes the full
  per-job range from the spec (D-08, D-09)
- Voice list reflects reality, not the long-dead OpenAI default
  list

## Why the rest of the spec was already satisfied

The original 999.13 spec called out "narration drags / subs drift /
slow TTS" symptoms. Recent commits had already addressed the root
causes:

| Spec requirement | Already done in |
|---|---|
| Bump TTS default for energy | commit 21a1831 (1.0/1.1 → 1.35 + flow hint) |
| Word-level timings preserved | quick task 260407-2cj |
| Scene durations from real narration | already in editor-store loadFromStepState |
| Char-offset alignment, full coverage | commits 3d21d3a, f56e164 |
| Sentence-aware boundaries | implicit — cena.narracao IS a sentence chunk |
| Scene splitter respects word-starved cenas | commit 8957444 |

This phase's job was to lock in the contract (drift assertion) and
surface the override (TTS speed UI), not to re-do the alignment
work.

## Notes

- The drift assertion is dev-only (`console.warn`) by design — it's
  a smoke alarm to catch upstream regressions, not a user-facing
  error. If a user ever reports drift in the wild, they can open
  devtools and we'll see the exact numbers in console.
- Did not add a backend control to set `tts_speed` per-cena —
  spec deferred that. If a user wants emphasis variation, they can
  edit the audio in the editor manually.
- Did not refactor `align_srt_with_script` because it's already
  doing the right thing (anchor-based char-offset mapping with
  contiguity invariant). Touching it now would be churn for no gain.
