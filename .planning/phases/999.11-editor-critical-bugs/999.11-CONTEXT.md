# Phase 999.11: Editor Critical Bugs - Context

**Gathered:** 2026-04-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix 10 data integrity, stability, and correctness bugs in the video editor. Every fix must be unit-tested (Vitest). Pure logic extracted to `src/lib/editor/` for reusability. No new features — only correctness and stability.

</domain>

<decisions>
## Implementation Decisions

### Playhead & sync strategy
- **D-01:** Single playhead source: RAF loop in RemotionPreview only. Remove the `timeupdate` event listener from Timeline.tsx entirely.
- **D-02:** `freezeFrame` must cascade subtitle/audio shifts using `shiftSubtitles` + `shiftAudio`, same pattern as `trimScene`. All duration-mutating operations must be consistent.

### Subtitle text safety
- **D-03:** contentEditable fix: use a local `useRef` to hold draft text while focused. Read from store only on mount/selection change, write back on blur. Prevents re-render clobbering.
- **D-04:** SRT fetch race: `AbortController` + generation counter in `loadFromStepState`. Discard stale fetch results if generation changed. Same pattern as `use-audio-waveform`.
- **D-05:** Duplicate IDs: replace all `Date.now()` ID generation in `parseSrt` and `splitSubtitle` with `genId("sub")` to match the rest of the codebase.

### Trim & cascade math
- **D-06:** Add `trimFrom` field to `EditorScene` (analogous to `EditorAudioItem.startFrom`). Left handle adjusts both `trimFrom` and `durationInFrames`. Remotion Scene component reads `trimFrom` to offset playback start.
- **D-07:** `trimScene` must apply min-duration clamp BEFORE computing cascade delta. `const clampedDuration = Math.max(15, newDuration); const delta = clampedDuration - oldDuration;`

### Resource lifecycle
- **D-08:** Singleton `AudioContext` (module-level). Cache waveform by `audioUrl` only (not `numSamples`). Resample peaks array client-side when zoom changes — no re-decode.
- **D-09:** Autosave cleanup: `AbortController` to cancel in-flight `patchEditorState` on unmount. `isMountedRef` to guard `setSaveStatus`. Clear secondary "idle" timeout in cleanup.
- **D-10:** Context menu stale offset: recompute `frameOffset` inside `SceneMenu` from live store state (scenes + playheadFrame), not from frozen `target.startFrame` captured at right-click.

### Architecture & testability
- **D-11:** Extract pure functions to `src/lib/editor/`: shift helpers, ID generation, SRT parsing, time math, cascade logic. Store imports from `lib/editor/`. Hooks stay in `hooks/`. Clean separation: logic vs state vs UI.
- **D-12:** Every fix gets dedicated unit tests in Vitest. Extend existing `editor-store.test.ts` for store actions. New test files for extracted `lib/editor/` utilities.
- **D-13:** Structure for reuse: editor utilities in `lib/editor/` will be importable by future phases (999.12 UX enhancements, any new editor features).

### Claude's Discretion
- Internal file structure within `lib/editor/` (how many files, naming)
- Test organization (one file per module vs grouped by feature)
- Whether to create a barrel export (`lib/editor/index.ts`)

</decisions>

## Existing Code Insights

### Reusable Assets
- `genId(prefix)` in editor-store.ts — ID generator with counter (should be extracted to lib/editor/)
- `shiftSubtitles`, `shiftAudio`, `getSceneTimeRange`, `subsInRange`, `subsOverlapping` — pure helper functions (should be extracted)
- `parseSrt`, `srtTimeToFrames` — SRT parsing (should be extracted)
- `reindexScenes` — scene reindexing (should be extracted)
- `useAudioWaveform` — has LRU cache pattern that waveform singleton should follow

### Established Patterns
- Zustand + zundo temporal for state management with undo/redo
- `partialize` excludes UI state from undo history
- `useStore(temporal, selector)` for reactive undo/redo state (fixed in this session)
- AbortController pattern in `use-audio-waveform.ts` — reuse for SRT fetch

### Integration Points
- `EditorScene` type needs `trimFrom?: number` field added
- `ReelComposition.tsx` and `Scene.tsx` need to read `trimFrom` for video offset
- `lib/editor/` is a new directory — no existing barrel exports to worry about

</code_context>
