# Phase 999.11: Editor Critical Bugs - Research

**Researched:** 2026-04-06
**Domain:** React video editor -- Zustand state management, Remotion rendering, Web Audio API, DOM contentEditable
**Confidence:** HIGH

## Summary

This phase fixes 10 distinct bugs in the video editor, all centered on data integrity, resource lifecycle, and cascade correctness. The codebase is a React 19 + Next.js 15 app using Zustand (with zundo temporal) for state, Remotion 4.0.445 for preview/render, and the Web Audio API for waveform decoding. All bugs are in well-defined code paths with clear root causes identified in the CONTEXT.md decisions.

The primary extraction target is `src/lib/editor/` -- a new directory for pure functions currently embedded in `editor-store.ts`. These pure functions (shift helpers, SRT parsing, ID generation, time math) have zero React/Zustand dependencies, making them trivially unit-testable with Vitest. The store actions become thin wrappers calling into these pure functions.

**Primary recommendation:** Group fixes by dependency -- extract `lib/editor/` pure functions first (foundation), then fix bugs that depend on them, then fix UI/lifecycle bugs that are independent. Every fix gets a dedicated unit test.

- **D-01:** Single playhead source: RAF loop in RemotionPreview only. Remove the `timeupdate` event listener from Timeline.tsx entirely.

### Pattern: Pure Function Extraction
**What:** Move functions from inside `editor-store.ts` to `lib/editor/` without changing their signatures.
**When to use:** Every function that has zero dependency on Zustand `set`/`get` or React hooks.
**Example:**
```typescript
// src/lib/editor/cascade.ts
export function shiftSubtitles(subs: EditorSubtitle[], afterFrame: number, delta: number): EditorSubtitle[] {
  return subs
    .map((s) => {
      if (s.startFrame >= afterFrame) {
        return { ...s, startFrame: s.startFrame + delta, endFrame: s.endFrame + delta };
      }
      if (s.endFrame > afterFrame) {
        return { ...s, endFrame: Math.max(s.startFrame + 1, s.endFrame + delta) };
      }
      return s;
    })
    .filter((s) => s.endFrame > s.startFrame && s.startFrame >= 0);
}
```

Then in `editor-store.ts`:
```typescript
import { shiftSubtitles, shiftAudio, getSceneTimeRange } from "@/lib/editor";
```

### Pattern: AbortController + Generation Counter for Fetch Races
**What:** Prevent stale async results from overwriting current state.
**When to use:** Any `fetch` inside a Zustand action where user can trigger multiple loads before the first completes.
**Example (for D-04):**
```typescript
// Module-level generation counter
let srtGeneration = 0;

// Inside loadFromStepState:
srtGeneration++;
const thisGen = srtGeneration;
const controller = new AbortController();
fetch(url, { signal: controller.signal, headers })
  .then((r) => r.text())
  .then((text) => {
    if (thisGen !== srtGeneration) return; // stale
    const subtitles = parseSrt(text, fps);
    if (subtitles.length > 0) set({ subtitles });
  })
  .catch(() => {});
```

### Pattern: Singleton AudioContext
**What:** Module-level `AudioContext` instance, reused across all waveform decodes.
**When to use:** `use-audio-waveform.ts` to prevent AudioContext leaks on zoom.
**Example (for D-08):**
```typescript
let sharedCtx: AudioContext | null = null;
function getAudioContext(): AudioContext {
  if (!sharedCtx || sharedCtx.state === "closed") {
    sharedCtx = new AudioContext();
  }
  return sharedCtx;
}

// Cache keyed by audioUrl only (not numSamples)
const rawCache = new Map<string, { peaks: Float32Array; duration: number }>();

// Resample peaks client-side for different numSamples
function resamplePeaks(source: Float32Array, targetCount: number): number[] {
  const result: number[] = [];
  const step = source.length / targetCount;
  for (let i = 0; i < targetCount; i++) {
    const start = Math.floor(i * step);
    const end = Math.min(Math.floor((i + 1) * step), source.length);
    let max = 0;
    for (let j = start; j < end; j++) {
      if (source[j] > max) max = source[j];
    }
    result.push(max);
  }
  return result;
}
```

### Pattern: Local Draft State for contentEditable
**What:** `useRef` holds draft text while focused, reads from store on mount/selection change, writes back on blur.
**When to use:** `SubtitleEditor.tsx` SubtitleOverlay component (D-03).
**Example:**
```typescript
const draftRef = useRef<string>(subtitle.text);
const editRef = useRef<HTMLDivElement>(null);

// Sync from store on mount or selection change
useEffect(() => {
  draftRef.current = subtitle.text;
  if (editRef.current && editRef.current.textContent !== subtitle.text) {
    editRef.current.textContent = subtitle.text;
  }
}, [subtitle.id, subtitle.text]);

const handleBlur = useCallback((e: React.FocusEvent<HTMLDivElement>) => {
  const newText = e.currentTarget.textContent ?? "";
  draftRef.current = newText;
  if (newText !== subtitle.text) {
    updateSubtitle(subtitle.id, { text: newText });
  }
}, [subtitle.id, subtitle.text, updateSubtitle]);
```
Important: Do NOT set `textContent` inside the contentEditable while it has focus -- that destroys the cursor position and causes the "text lost on re-render" bug.

### Anti-Patterns to Avoid
- **Dual playhead sync (D-01):** Never have both RAF and `timeupdate` updating the same store field. The RAF loop in RemotionPreview is authoritative.
- **Date.now() for IDs (D-05):** `Date.now()` can produce duplicates when called in a tight loop (same millisecond). Always use `genId(prefix)` which includes a monotonic counter.
- **Clamp after delta (D-07):** Computing `delta = newDuration - oldDuration` before clamping means the cascade shift is wrong when the clamp activates. Always clamp first.
- **AudioContext per decode (D-08):** Creating `new AudioContext()` on every zoom change leaks browser resources. Browsers limit to ~6 concurrent contexts.

This is the same pattern already used for `<Audio trimBefore={item.startFrom ?? 0}>` in `ReelComposition.tsx`.

## Common Pitfalls

### Pitfall 1: trimScene cascade delta computed with wrong duration
**What goes wrong:** `trimScene` computes `delta = newDuration - oldDuration` but then clamps to `Math.max(15, newDuration)`. If user drags to 5 frames, delta is -oldDuration+5, but clamped duration is 15. Subtitles shift by wrong amount.
**Why it happens:** Clamp applied to scene but not to delta calculation.
**How to avoid:** Per D-07: `const clampedDuration = Math.max(15, newDuration); const delta = clampedDuration - oldDuration;`
**Warning signs:** Subtitles misaligned after trimming a scene to minimum duration.

### Pitfall 2: AudioContext leak on zoom
**What goes wrong:** `useAudioWaveform` creates `new AudioContext()` per invocation. Zooming changes `numSamples`, causing re-decode with a new context. After ~6 contexts, browser silently fails.
**Why it happens:** Cache key includes `numSamples`, so zoom change = cache miss = new decode = new AudioContext.
**How to avoid:** Per D-08: singleton AudioContext, cache raw decoded data by URL only, resample peaks client-side.
**Warning signs:** Waveforms stop rendering after several zoom operations, console warnings about AudioContext limits.

### Pitfall 3: contentEditable text lost on re-render
**What goes wrong:** React re-renders SubtitleOverlay when store updates (e.g., playhead moves). The `{subtitle.text}` child of the contentEditable div resets to the store value, discarding whatever the user was typing.
**Why it happens:** contentEditable DOM state is not controlled by React. When React reconciles, it overwrites the DOM text node with the prop value.
**How to avoid:** Per D-03: useRef for draft text, only sync from store when `subtitle.id` changes (not every render), write back on blur.
**Warning signs:** Characters disappear while typing in the subtitle overlay.

### Pitfall 4: SRT fetch race condition
**What goes wrong:** User loads a new reel quickly after the first. The first SRT fetch completes and overwrites subtitles for the second reel.
**Why it happens:** `loadFromStepState` fires a fetch with no cancellation. The `.then()` closure captures stale state.
**How to avoid:** Per D-04: AbortController + generation counter. Discard results if generation changed.
**Warning signs:** Wrong subtitles appearing after rapid navigation between reels.

### Pitfall 5: Context menu frameOffset computed at right-click time
**What goes wrong:** `getContextTarget` in Timeline.tsx computes `startFrame` when the context menu target is set. If the user played or seeked between right-click and clicking "Split," the offset is stale.
**Why it happens:** `target.startFrame` is a snapshot from the `handleCtx` callback, not live state.
**How to avoid:** Per D-10: SceneMenu should compute `frameOffset` from live store state inside the menu render, not rely on `target.startFrame`.
**Warning signs:** Split creates scenes with unexpected durations, especially after playing then right-clicking.

### Pitfall 6: freezeFrame not cascading
**What goes wrong:** `freezeFrame` increases `durationInFrames` but does not shift subtitles or audio after the frozen scene. Everything after the scene is now misaligned by `framesToFreeze` frames.
**Why it happens:** `freezeFrame` is a simple map over scenes, unlike `trimScene` which calls `shiftSubtitles`/`shiftAudio`.
**How to avoid:** Per D-02: apply `shiftSubtitles(subs, range.end, framesToFreeze)` and `shiftAudio(audio, range.end, framesToFreeze)` just like `trimScene` does.
**Warning signs:** Audio and subtitles desync after freezing a frame.

### Fix (D-07):
```typescript
trimScene: (sceneId, newDuration) => {
  set((state) => {
    const idx = state.scenes.findIndex((s) => s.id === sceneId);
    if (idx === -1) return state;
    const oldDuration = state.scenes[idx].durationInFrames;
    const clampedDuration = Math.max(15, newDuration);
    const delta = clampedDuration - oldDuration;
    if (delta === 0) return state;
    const range = getSceneTimeRange(state.scenes, idx);
    const scenes = state.scenes.map((s) =>
      s.id === sceneId ? { ...s, durationInFrames: clampedDuration } : s,
    );
    const subtitles = shiftSubtitles(state.subtitles, range.end, delta);
    const audioItems = shiftAudio(state.audioItems, range.end, delta);
    return { scenes, subtitles, audioItems };
  });
},
```

## Open Questions

1. **Video left-trim handle behavior with trimFrom**
   - What we know: Audio left-trim adjusts `from` + `startFrom` + `durationInFrames`. Video scenes don't have a `from` (they are sequential via TransitionSeries).
   - What's unclear: When the user drags the left handle on a video scene, should `trimFrom` increase (revealing later part of source) while `durationInFrames` decreases? Or should it behave differently from audio?
   - Recommendation: Match audio behavior -- left handle increases `trimFrom` and decreases `durationInFrames` by the same amount. This is semantically "trim the beginning of the source clip." The cascade shift to subtitles/audio still comes from the duration change.

2. **Autosave AbortController interaction with rapid state changes**
   - What we know: The 2s debounce timer already prevents rapid saves. The AbortController cancels the in-flight request.
   - What's unclear: If a save is in-flight and user makes another change, should we abort the save (potentially losing data) or let it complete?
   - Recommendation: Abort the in-flight save and start a new 2s timer. The new save will include all current state. This is safe because the save is idempotent (PATCH with full state).
