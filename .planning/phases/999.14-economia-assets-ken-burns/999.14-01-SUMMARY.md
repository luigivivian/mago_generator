# Plan 01 — Economic mode backend

## What landed

**Migration 030**: Adds `economic_mode BOOLEAN NOT NULL DEFAULT FALSE`
to the `reels_config` table. Chains from 029.

**ReelsConfig (SQLAlchemy)**: New `economic_mode: Mapped[bool]` column
with `default=False, server_default="0"` matching the migration.

**ReelsConfigRequest / ReelsConfigResponse (Pydantic)**: Both gain
`economic_mode: Optional[bool] = False` / `bool = False` so the field
flows through the API contract.

**Pipeline (`run_step_video_kie`)**:
- Reads `self.config.get("economic_mode")` once at the start
- Skips the per-job credit total pre-check when economic mode is on
  (no Kie credits will be consumed, so no pre-check needed)
- Short-circuits BEFORE the GCS upload + Kie task creation phase:
  loops over `image_paths`, calls existing `_make_static(img_path,
  clip_path, clip_dur)` for every scene, marks status `success`
  with `static: True`
- Concats the resulting clips with audio + subtitles via the same
  `concat_clips_with_audio` call as the dynamic path
- Returns the final video path identically to the dynamic path

**Pipeline (alignment / splitter step)**:
- Read `economic_mode` flag from config
- `effective_max = 30.0 if economic_mode else SCENE_MAX_DURATION`
- Both the `has_long` detection AND the `split_long_scenes_in_script`
  call now use `effective_max`. With max=30s, no real cena will ever
  trigger a split, so the splitter is effectively disabled in
  economic mode.

## How it satisfies the must-haves

- `economic_mode` column on the table (D-11)
- API contract carries `economic_mode` (D-01)
- Video step routes through `_make_static` for every scene (D-03)
- Splitter is bypassed via the `effective_max` raise (D-04, D-12)

## Notes

- The economic-mode short-circuit returns the same shape as the
  dynamic path, so no caller code needs to know which mode ran.
- `_make_static` was already in place from the existing fallback
  logic — no new ffmpeg invocation needed.
- Did NOT add a server-side ffmpeg `zoompan` filter — the spec said
  "with Ken Burns applied" but applying it server-side would make
  the static clip non-static and force re-render every time the user
  edits in the editor. Applying motion at the editor render layer
  via Remotion `interpolate` is cheaper and reversible. That happens
  in Plan 02.
- The credit pre-check guard (`if user_id and not economic_mode:`)
  means economic-mode jobs cost zero Kie credits, which is the whole
  point of the feature.
