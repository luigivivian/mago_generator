# Plan 01 — Multi-select model + bulk ops + click-deselect

## What landed

**editor-types.ts**: Added `SelectableKind` union, `SelectableRef`,
`selectionKey()` and `parseSelectionKey()` helpers. Selection items
encoded as `${kind}:${id}` strings so they live in a single `Set<string>`.

**editor-store.ts**:
- New state field `selection: Set<string>`.
- Existing `setSelectedScene/Subtitle/Audio` actions also populate
  `selection` with a single entry — preserves backward compatibility
  with the scalar `selectedSceneId`/etc fields used by PropertiesPanel
  and Timeline track-label highlighting.
- New actions: `toggleSelection`, `addToSelection`, `replaceSelection`,
  `clearSelection`, `bulkDeleteSelected`, `bulkDuplicateSelected`.
- `bulkDeleteSelected` performs all deletions inside a single `set`
  callback — zundo records ONE undo entry for the whole bulk op.
  Order: scenes (cascade subtitles/audio) → subtitles → audio.
  Scene deletions iterated highest-index-first so frame ranges remain
  valid as later content shifts backward.
- `bulkDuplicateSelected` does scenes (full clone with subtitle/audio
  cascade via existing `subsInRange`/`shiftSubtitles`/`shiftAudio`)
  and subtitles. Audio duplication deferred — would collide with
  source.
- `selection` excluded from temporal `partialize` so undo/redo only
  tracks document state, not UI state.

**TimelineBlock.tsx**: `onSelect` callback now receives the
`React.MouseEvent` so the parent can read modifier keys.

**TimelineTrack.tsx**:
- Accepts `selectedIds?: Set<string>` in addition to legacy
  `selectedId` — set takes precedence when provided.
- New `onEmptyClick` prop. Background pointerdown (where
  `e.target === e.currentTarget`) calls it. Wired to `clearSelection`.

**Timeline.tsx**:
- Reads `selection` and derives per-track `Set<string>` for the three
  tracks (scenes, subtitles, audio).
- New `handleSceneSelect/SubtitleSelect/AudioSelect` route the click:
  `e.shiftKey || e.metaKey || e.ctrlKey` → `toggleSelection`,
  otherwise `replaceSelection`.
- New keyboard listener: `Delete`/`Backspace` → `bulkDeleteSelected`,
  `Cmd/Ctrl+D` → `bulkDuplicateSelected`. Skipped when focus is in
  any text input/textarea/contenteditable so PropertiesPanel and
  inline subtitle editor still receive their keys.

**PropertiesPanel.tsx**: When `selection.size > 1`, renders a compact
summary "N itens selecionados" with kind breakdown
(`X cenas · Y legendas · Z audios`) and two buttons:
"Duplicar todos (Cmd+D)" and "Excluir todos (Delete)".

## How it satisfies the must-haves

- **Multi-select with shift/cmd-click**: Click handler routes through
  `toggleSelection` when modifier is present, set membership drives
  block highlighting via `selectedIds`.
- **Bulk delete/duplicate as single undo entry**: Both bulk methods
  use a single `set()` call so zundo's temporal middleware records
  exactly one history entry per bulk op.
- **Click empty area deselects**: Track background `onPointerDown`
  with `e.target === e.currentTarget` check fires `clearSelection()`.
- **Backward compat**: Existing scalar selection fields and actions
  remain functional. PropertiesPanel falls back to single-item view
  when `selection.size <= 1`.

## Notes

- Did not add new vitest cases for bulk ops yet — the existing
  `editor-store.test.ts` exercises all the underlying primitives
  (`shiftSubtitles`, `shiftAudio`, `getSceneTimeRange`) and bulk
  operations are thin compositions over them. A future test pass
  could add explicit bulk-undo regression tests.
- Audio bulk duplicate is intentionally deferred — placing a duplicate
  of an audio item creates a positional collision with the source
  that needs UX design (offset by N frames? require user click?).
  Tracked in 999.12 deferred ideas.
