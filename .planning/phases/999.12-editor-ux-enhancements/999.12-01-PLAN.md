   - Add state field `selection: Set<string>` (encode as `${kind}:${id}` keys)
   - Keep existing `selectedSceneId`/`selectedSubtitleId`/`selectedAudioId` as derived getters via Zustand selectors — update setSelectedScene/Subtitle/Audio to ALSO populate `selection` with single entry `${kind}:${id}`
   - Add new actions:
     - `toggleSelection(kind, id)` — flips membership, deselects same-kind scalars when applicable
     - `addToSelection(kind, id)` — additive (for shift-click)
     - `replaceSelection(kind, id)` — single-select (backward compat)
     - `clearSelection()` — empties set, nulls all scalars
     - `bulkDeleteSelected()` — iterates set, calls per-kind delete actions inside ONE `set` callback so zundo records ONE history entry; remove keys from selection at end
     - `bulkDuplicateSelected()` — same pattern, calls duplicateScene/addSubtitle clones
   - For bulkDeleteSelected: collect scene IDs, sub IDs, audio IDs from selection; perform direct state mutation (one set call) using existing helpers from lib/editor: filter scenes via `s.id ∉ deletedSet`, run `shiftSubtitles`/`shiftAudio` cumulatively for each removed scene's range using getSceneTimeRange BEFORE removal. Order: scenes first (cascade subtitles/audio), then subtitles, then audio items.

3. Persist `selection` exclusion in temporal partialize: do NOT include `selection` in undo history (selection is UI state, not document state).
