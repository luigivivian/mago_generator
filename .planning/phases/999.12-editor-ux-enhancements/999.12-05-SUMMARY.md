# Plan 05 — Pre-export validation + export progress modal

## What landed

**lib/editor/validate.ts** (new):
- Pure `validateEditorState(scenes, subtitles, audioItems)` returns
  `ValidationIssue[]`
- Errors: no scenes, scene with no clip/img, scene with zero duration
- Warnings: audio extending beyond timeline, subtitles overlapping >50%
  of the shorter sub's duration
- `hasErrors(issues)` helper

**ExportModal.tsx** (new):
- Stages: `validating → ready → exporting → done | failed`
- On open, runs validation; if errors → only "Fechar" button shown.
  If warnings only → "Exportar mesmo assim" button. If clean → normal
  "Exportar" button.
- Click export → `exportRemotion(jobId)`, switch to `exporting` stage
- Watches `useStepState(jobId).video.export_status` field which the
  backend already writes during `_export_remotion_task`. The existing
  SWR hook polls every 2s, so no new polling code needed.
- Status mapping:
  - `rendering` → spinner + "Renderizando..."
  - `complete` → green checkmark + Download button (links to
    `/api/reels/{jobId}/file?path=editor-export.mp4`)
  - `failed` → red error + `step_state.video.export_error`
- Modal stays open until user closes (so they can re-download)
- Click outside or X → closes

**api.ts**: Extended `StepState.video` type with optional
`export_status` ("rendering" | "complete" | "failed") and
`export_error` (string).

**Toolbar.tsx**:
- Removed local `exporting` state and direct `exportRemotion` call
- New `exportModalOpen` state
- Export button just sets `exportModalOpen(true)`
- Renders `<ExportModal>` at the bottom

## How it satisfies the must-haves

- Pure validate function — testable in isolation, lives in lib/editor
- Errors block (no Export button shown), warnings show "Export anyway"
- Polling reuses existing SWR with 2s interval — no new infra
- Backend `_export_remotion_task` already writes `export_status` so
  no Python changes were needed

## Notes

- Did not write a unit test for `validateEditorState` yet — pure
  function so trivial to test, can be added in a tests pass.
- The download link assumes the export file lives at
  `editor-export.mp4` inside the job dir, which matches the backend's
  `output_path` constant in `_export_remotion_task`.
- Validation runs on every open of the modal — not memoized across
  opens. Acceptable: scenes can change between opens, and the cost is
  trivial.
- The export modal does not show a percentage progress bar because
  the backend doesn't expose one — the spinner + "Renderizando" copy
  is honest. Adding a real progress channel would require streaming
  Remotion's stdout via SSE, which is out of scope.
