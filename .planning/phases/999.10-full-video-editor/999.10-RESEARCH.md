# Phase 999.10: Full In-Browser Video Editor - Research

**Researched:** 2026-04-05
**Domain:** React video editor (Remotion + timeline UI + drag-and-drop + state management)
**Confidence:** HIGH

## Summary

This phase builds a VEED.io-style video editor integrated into memeLab, enabling scene-by-scene editing of generated reels. The architecture is centered on Remotion as both the preview engine (via `@remotion/player`) and the export engine (via Remotion CLI on the backend). The editor page lives at `/reels/[id]/edit` and loads existing `step_state` data (clips, audio, SRT, script) into a Zustand store that drives both the Remotion Player preview and the custom timeline UI.

The key technical challenges are: (1) integrating Remotion Player into the existing Next.js 15 App Router with `"use client"` + dynamic import, (2) building a multi-track timeline with drag-and-drop via `@dnd-kit/sortable`, (3) implementing undo/redo via Zustand + zundo temporal middleware, (4) representing the editor state as a typed data model that maps cleanly to Remotion `<TransitionSeries>` and `<Sequence>` components, and (5) server-side export via Remotion CLI triggered from a FastAPI endpoint.

**Primary recommendation:** Use Remotion 4.0.445 with `@remotion/player` for preview, Zustand + zundo for state management with undo/redo, `@dnd-kit/sortable` (legacy v10 with `--legacy-peer-deps`) for drag-and-drop, and a custom timeline component built with Tailwind CSS + framer-motion. Export via Remotion CLI subprocess on the backend (Node.js process spawned from FastAPI).

### Pattern 1: Remotion Player Integration in Next.js 15 App Router

**What:** Dynamic import with `ssr: false` inside a `"use client"` wrapper component.
**When to use:** Any component that imports from `@remotion/player`.
**Why:** Remotion Player uses browser APIs (window, document) that crash in Node.js SSR.

```tsx

import { useMemo, useRef } from "react";
import type { PlayerRef } from "@remotion/player";

const Player = dynamic(
  () => import("@remotion/player").then((mod) => mod.Player),
  { ssr: false }
);

export function RemotionPreview({ tracks, playerRef }: {
  tracks: EditorTrack[];
  playerRef: React.RefObject<PlayerRef>;
}) {
  const inputProps = useMemo(() => ({ tracks }), [tracks]);

  return (
    <Player
      ref={playerRef}
      component={ReelComposition}
      compositionWidth={1080}
      compositionHeight={1920}
      fps={30}
      durationInFrames={totalFrames}
      inputProps={inputProps}
      style={{ width: "100%", height: "auto" }}
    />
  );

```

### Pattern 2: Zustand Store with Temporal (Undo/Redo) Middleware

**What:** Zustand store wrapped in `temporal` middleware from zundo for time-travel.
**When to use:** All editor state mutations.
**Why:** Under 700 bytes, proven in React Flow; supports pause/resume tracking for batch operations.

```tsx
// src/stores/editor-store.ts
import { create } from "zustand";
import { temporal } from "zundo";

interface EditorState {
  scenes: EditorScene[];
  subtitles: EditorSubtitle[];
  transitions: EditorTransition[];
  selectedSceneId: string | null;
  selectedSubtitleId: string | null;
  playheadFrame: number;

  // Actions
  reorderScenes: (fromIndex: number, toIndex: number) => void;
  trimScene: (sceneId: string, newDuration: number) => void;
  duplicateScene: (sceneId: string) => void;
  deleteScene: (sceneId: string) => void;
  updateSubtitle: (id: string, updates: Partial<EditorSubtitle>) => void;
  setTransition: (sceneId: string, transition: EditorTransition) => void;
  setSelectedScene: (id: string | null) => void;
  loadFromStepState: (stepState: StepState) => void;
}

export const useEditorStore = create<EditorState>()(
  temporal(
    (set) => ({
      scenes: [],
      subtitles: [],
      transitions: [],
      selectedSceneId: null,
      selectedSubtitleId: null,
      playheadFrame: 0,

      reorderScenes: (from, to) => set((s) => {
        const scenes = [...s.scenes];
        const [moved] = scenes.splice(from, 1);
        scenes.splice(to, 0, moved);
        return { scenes };
      }),
      // ... other actions
    }),
    {
      // Only track meaningful state changes (not selection/playhead)
      partialize: (state) => ({
        scenes: state.scenes,
        subtitles: state.subtitles,
        transitions: state.transitions,
      }),
    }
  )
);

// Undo/redo access
export const useTemporalStore = () =>
  useEditorStore.temporal.getState();
```
Source: [zundo GitHub](https://github.com/charkour/zundo)

### Pattern 3: Remotion Composition with TransitionSeries

**What:** Map editor state to Remotion `<TransitionSeries>` with scenes as `<Video>` or `<Img>` components.
**When to use:** The main Remotion composition that both Player and CLI render.

```tsx
// src/remotion/ReelComposition.tsx
import { AbsoluteFill, useVideoConfig } from "remotion";
import { TransitionSeries, linearTiming } from "@remotion/transitions";
import { fade } from "@remotion/transitions/fade";
import { slide } from "@remotion/transitions/slide";
import { Video } from "@remotion/media";
import { Audio } from "@remotion/media";

const TRANSITION_MAP = { fade: fade(), slide: slide(), none: null };

export const ReelComposition: React.FC<{ tracks: EditorTrack[] }> = ({ tracks }) => {
  const { fps } = useVideoConfig();
  const videoTrack = tracks.find(t => t.type === "video");
  const audioTrack = tracks.find(t => t.type === "audio");

  return (
    <AbsoluteFill style={{ backgroundColor: "#000" }}>
      {/* Video scenes with transitions */}
      <TransitionSeries>
        {videoTrack?.items.map((scene, i) => (
          <React.Fragment key={scene.id}>
            <TransitionSeries.Sequence durationInFrames={scene.durationInFrames}>
              {scene.clipUrl ? (
                <Video src={scene.clipUrl} style={{ width: "100%", height: "100%" }} />
              ) : (
                <Img src={scene.imgUrl} style={{ width: "100%", height: "100%", objectFit: "cover" }} />
              )}
            </TransitionSeries.Sequence>
            {scene.transition && i < videoTrack.items.length - 1 && (
              <TransitionSeries.Transition
                presentation={TRANSITION_MAP[scene.transition.type]}
                timing={linearTiming({ durationInFrames: Math.round(scene.transition.duration * fps) })}
              />
            )}
          </React.Fragment>
        ))}
      </TransitionSeries>

      {/* Audio narration */}
      {audioTrack?.items.map(item => (
        <Sequence key={item.id} from={item.from} durationInFrames={item.durationInFrames}>
          <Audio src={item.audioUrl} />
        </Sequence>
      ))}

      {/* Subtitle overlay */}
      <SubtitleOverlay subtitles={subtitleTrack?.items ?? []} />
    </AbsoluteFill>
  );
};
```
Source: Remotion skill rules/transitions.md, rules/sequencing.md

### Pattern 5: Autosave with Debounce

**What:** Debounced PATCH to backend 2s after each state change.
**When to use:** Every editor action that modifies scenes/subtitles/transitions.

```tsx
// src/hooks/use-autosave.ts
import { useEffect, useRef, useState } from "react";
import { useEditorStore } from "@/stores/editor-store";

export function useAutosave(jobId: string) {
  const [saveStatus, setSaveStatus] = useState<"idle" | "saving" | "saved">("idle");
  const timerRef = useRef<NodeJS.Timeout>();
  const scenes = useEditorStore((s) => s.scenes);
  const subtitles = useEditorStore((s) => s.subtitles);
  const transitions = useEditorStore((s) => s.transitions);

  useEffect(() => {
    if (timerRef.current) clearTimeout(timerRef.current);
    timerRef.current = setTimeout(async () => {
      setSaveStatus("saving");
      await patchEditorState(jobId, { scenes, subtitles, transitions });
      setSaveStatus("saved");
      setTimeout(() => setSaveStatus("idle"), 1500);
    }, 2000);

    return () => { if (timerRef.current) clearTimeout(timerRef.current); };
  }, [scenes, subtitles, transitions, jobId]);

  return saveStatus;
}
```

### Anti-Patterns to Avoid

- **Remotion composition importing app code:** Keep `src/remotion/` self-contained. The composition must NOT import from `src/components/` or `src/stores/`. Data flows in via `inputProps` only.
- **Mutable state in Remotion components:** Remotion re-renders per frame. Never use `useState` or `useEffect` with side effects inside compositions. Use `useCurrentFrame()` and pure computations.
- **Calling bundle() per render:** The Remotion bundle should be pre-built once and reused. Creating a bundle for every export is an anti-pattern that wastes minutes.
- **Not memoizing inputProps:** Passing unmemoized objects to `<Player inputProps={...}>` causes full re-renders on every frame update. Always wrap in `useMemo()`.
- **Tailwind transition/animate classes in Remotion:** Never use `transition-*` or `animate-*` CSS classes inside Remotion compositions. Always animate with `useCurrentFrame()` + `interpolate()`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Undo/redo | Custom history stack with command objects | `zundo` temporal middleware | Handles edge cases (batch ops, partial state, pause/resume), <700 bytes |
| Video preview | HTML5 video element with custom controls | `@remotion/player` with PlayerRef API | Frame-accurate preview, identical to export output, built-in seek/play |
| Scene transitions | Manual opacity/transform animations between clips | `@remotion/transitions` TransitionSeries | Handles duration overlap calculation, timing functions, 5+ transition types |
| Audio waveform | Web Audio API with manual canvas drawing | `@remotion/media-utils` visualizeAudioWaveform() | Frame-synced, handles windowed data loading, SVG path generation |
| SRT parsing | Custom regex parser | `@remotion/captions` parseSrt() | Handles edge cases in SRT format, produces typed Caption objects |
| Drag-and-drop | HTML5 drag API or manual pointer events | `@dnd-kit/sortable` | Accessible, handles keyboard DnD, collision detection, smooth animations |
| Subtitle display | Manual frame-by-frame text rendering | `@remotion/captions` createTikTokStyleCaptions() | Word grouping, page splitting, token-level highlighting |

**Key insight:** Remotion's ecosystem handles all the video-specific complexity (frame math, transition overlap, audio sync). Building custom solutions would mean reimplementing frame-accurate rendering that Remotion already solves.

## Common Pitfalls

### Pitfall 1: Remotion Version Mismatch
**What goes wrong:** Installing `remotion` and `@remotion/*` packages with `^` allows npm to resolve different minor versions, causing cryptic runtime errors.
**Why it happens:** Remotion's internal APIs change between minor versions; packages must be identical.
**How to avoid:** Always use `--save-exact` and confirm all `@remotion/*` packages show the same version in `package-lock.json`.
**Warning signs:** "Cannot read property of undefined" errors from Remotion internals.

### Pitfall 2: SSR Crash from Remotion Imports
**What goes wrong:** Importing `@remotion/player` in a Server Component causes `ReferenceError: window is not defined`.
**Why it happens:** Remotion uses browser globals (window, document). Next.js 15 App Router defaults to Server Components.
**How to avoid:** Always use `"use client"` + `next/dynamic` with `{ ssr: false }` for any component that imports Remotion.
**Warning signs:** Server-side render errors mentioning `window`, `document`, or `navigator`.

### Pitfall 3: Player Re-render Storm
**What goes wrong:** Every frame update triggers full component tree re-render, causing janky playback.
**Why it happens:** Playhead position state lives in parent component alongside Player; `inputProps` not memoized.
**How to avoid:** (1) Keep Player and controls as siblings, not parent-child. (2) Wrap `inputProps` in `useMemo()`. (3) Use `PlayerRef` for all control interactions instead of state.
**Warning signs:** Sluggish playback, high CPU during preview, React DevTools showing excessive re-renders.

### Pitfall 4: TransitionSeries Duration Miscalculation
**What goes wrong:** Total composition duration doesn't match expected length; scenes appear cut off or have dead frames.
**Why it happens:** Transitions OVERLAP scenes, reducing total duration. Two 60-frame scenes with a 15-frame transition = 105 frames, not 120.
**How to avoid:** Calculate total duration as `sum(sceneDurations) - sum(transitionDurations)`. Use `timing.getDurationInFrames({ fps })` for spring timings.
**Warning signs:** Black frames at end, or scenes appearing to start too early.

### Pitfall 5: Zundo Tracking Non-Essential State
**What goes wrong:** Undo/redo triggers on selection changes, playhead moves, or UI-only state.
**Why it happens:** Default zundo tracks all state changes.
**How to avoid:** Use `partialize` option to only track meaningful state (scenes, subtitles, transitions). Exclude `selectedSceneId`, `playheadFrame`, `zoom`, etc.
**Warning signs:** Pressing undo changes selection instead of reverting content changes.

### Pitfall 6: @remotion/bundler in API Routes
**What goes wrong:** `@remotion/bundler` includes Webpack, which cannot be bundled by Webpack (circular dependency).
**Why it happens:** Next.js API routes are bundled with Webpack.
**How to avoid:** Pre-build the Remotion bundle as a build step. Reference the output folder from the render endpoint. For this project: use Remotion CLI subprocess from FastAPI, not Next.js API routes.
**Warning signs:** Build errors about Webpack self-bundling; infinite bundling loops.

### Pitfall 7: dnd-kit Peer Dependency Warnings with React 19
**What goes wrong:** `npm install` fails with peer dependency conflicts.
**Why it happens:** Legacy `@dnd-kit/core` and `@dnd-kit/sortable` declare `react@>=16.8.0` as peer dep but npm strict mode may reject React 19.
**How to avoid:** Use `--legacy-peer-deps` flag during installation.
**Warning signs:** npm error about peer dependency resolution.

### Server-Side Export via Remotion CLI (FastAPI)

```python
# Backend endpoint concept: POST /reels/{job_id}/export-remotion
import subprocess
import json
import os

async def export_remotion_video(job_id: str, editor_state: dict, job_dir: str):
    """Spawn Remotion CLI render process."""
    props_path = os.path.join(job_dir, "remotion-props.json")
    output_path = os.path.join(job_dir, "final_remotion.mp4")

    with open(props_path, "w") as f:
        json.dump({"tracks": editor_state["tracks"]}, f)

    # Remotion CLI must be run from the memelab directory where node_modules lives
    result = subprocess.run(
        [
            "npx", "remotion", "render",
            "src/remotion/index.ts",      # entry point
            "ReelEditor",                 # composition ID
            output_path,
            f"--props={props_path}",
            "--codec=h264",
            "--crf=18",
        ],
        cwd="memelab",
        capture_output=True,
        text=True,
        timeout=300,  # 5 minute timeout
    )

    if result.returncode != 0:
        raise RuntimeError(f"Remotion render failed: {result.stderr}")

    return output_path
```

### PlayerRef Custom Controls

```tsx
// Using PlayerRef for toolbar play/pause/seek
import type { PlayerRef } from "@remotion/player";

function Toolbar({ playerRef }: { playerRef: React.RefObject<PlayerRef> }) {
  const [playing, setPlaying] = useState(false);
  const { undo, redo } = useTemporalStore();

  useEffect(() => {
    const player = playerRef.current;
    if (!player) return;

    const onPlay = () => setPlaying(true);
    const onPause = () => setPlaying(false);
    player.addEventListener("play", onPlay);
    player.addEventListener("pause", onPause);
    return () => {
      player.removeEventListener("play", onPlay);
      player.removeEventListener("pause", onPause);
    };
  }, [playerRef]);

  return (
    <div className="flex items-center gap-2">
      <button onClick={() => playerRef.current?.toggle()}>
        {playing ? <Pause /> : <Play />}
      </button>
      <button onClick={() => undo()}>
        <Undo2 />
      </button>
      <button onClick={() => redo()}>
        <Redo2 />
      </button>
    </div>
  );
}
```

### Audio Waveform for Timeline

```tsx
// Using @remotion/media-utils for timeline waveform visualization
import { useWindowedAudioData, visualizeAudioWaveform } from "@remotion/media-utils";
import { createSmoothSvgPath } from "@remotion/media-utils";

function AudioWaveform({ audioUrl, width, height }: Props) {
  const frame = useCurrentFrame();
  const { fps } = useVideoConfig();

  const { audioData, dataOffsetInSeconds } = useWindowedAudioData({
    src: audioUrl,
    frame,
    fps,
    windowInSeconds: 30,
  });

  if (!audioData) return <div style={{ width, height }} />;

  const waveform = visualizeAudioWaveform({
    fps, frame, audioData,
    numberOfSamples: 256,
    windowInSeconds: 0.5,
    dataOffsetInSeconds,
  });

  const path = createSmoothSvgPath({
    points: waveform.map((y, i) => ({
      x: (i / (waveform.length - 1)) * width,
      y: height / 2 + (y * height) / 2,
    })),
  });

  return (
    <svg width={width} height={height}>
      <path d={path} fill="none" stroke="#7C3AED" strokeWidth={1} />
    </svg>
  );
}
```

## State of the Art

|--------------|------------------|--------------|--------|
| FFmpeg CLI assembly (current backend) | Remotion React compositions | Remotion v4 (2024+) | WYSIWYG preview identical to export; scene-level editing |
| react-beautiful-dnd | @dnd-kit (legacy) or @dnd-kit/react (new) | 2023+ (rbdnd deprecated) | dnd-kit is the standard; new API still in v0.x |

**Deprecated/outdated:**
- `react-beautiful-dnd`: Officially deprecated by Atlassian. Do not use.
- `@remotion/tailwind` (v3): Use `@remotion/tailwind-v4` for Tailwind CSS 4 projects.
- `Remotion v3 renderFrames() + stitchFramesToVideo()`: Replaced by unified `renderMedia()` in v3+.

## Open Questions

1. **Remotion bundle for CLI render on Python backend**
   - What we know: `npx remotion render` works from CLI with entry point path. FastAPI can spawn subprocess.
   - What's unclear: Whether the Remotion project needs its own `package.json` or can share `memelab/package.json`. Whether Chrome headless needs separate installation on the server.
   - Recommendation: Use `memelab/` as the cwd for `npx remotion render`. Chrome is bundled with Remotion's renderer. Test locally first.

2. **Asset URL resolution in Remotion compositions**
   - What we know: Clips are served via `/api/reels/{jobId}/file/{path}` which proxies to FastAPI. In Player (browser), this works via relative URLs.
   - What's unclear: During CLI render (server-side), relative URLs won't resolve. Need absolute URLs pointing to running FastAPI server.
   - Recommendation: Pass base URL as a prop to the composition. In browser: `window.location.origin`. In CLI render: `http://127.0.0.1:8000` or configurable.

3. **Tailwind CSS 4 in Remotion compositions**
   - What we know: `@remotion/tailwind-v4` exists but is marked experimental. Need webpack override in `remotion.config.ts`.
   - What's unclear: Whether it conflicts with the existing Tailwind 4 setup in `memelab/`.
   - Recommendation: Start without Tailwind in Remotion compositions (use inline styles). Add `@remotion/tailwind-v4` if needed later -- compositions are simple enough to not need it.

4. **next.config.ts modification for Remotion**
   - What we know: Need to add `serverExternalPackages: ['@remotion/renderer']` if using Node.js renderer. But we use CLI subprocess from FastAPI instead.
   - What's unclear: Whether just having `@remotion/player` installed causes Next.js build issues.
   - Recommendation: If build issues arise, add `transpilePackages: ['remotion', '@remotion/player']` to next.config.ts.
