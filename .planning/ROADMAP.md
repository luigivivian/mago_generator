## Phase Details

### Phase 22: Per-Cena TTS Anchoring
**Goal**: A reels job's TTS step produces one Gemini TTS file per cena, each with its real duration measured and persisted as ground truth for all downstream steps.
**Depends on**: Nothing (foundation refactor — v3.0 baseline)
**Requirements**: TTS-01, TTS-02, TTS-03, TTS-04, TTS-05, TTS-06
**Success Criteria** (what must be TRUE):
  1. Running `/reels/{jobId}/step/tts` produces one audio file per `script.cenas[i]` in addition to the concatenated `narracao_completa`
  2. After the step completes, `step_state.tts.cenas[i].duration` contains a float (ffprobe-measured) for every cena, and `sum(cenas[i].duration)` equals the duration of `narracao_completa.wav` (within 50ms tolerance from the ffmpeg concat)
  3. A biblical reel (`tone == "biblical"`) produces audio at `speaking_rate = 1.0`, audibly slower than a non-biblical reel of the same text
  4. Failure of a single cena during generation leaves the other cenas intact, marks the failed cena in `step_state.tts.cenas[i].failed = true`, and allows selective retry without re-running the whole step
  5. The editor still loads and plays the waveform for `narracao_completa.wav` unchanged (compat preserved)
**Plans**: TBD

### Phase 23: Audio-Anchored Timing Propagation
**Goal**: Every downstream timing consumer (clip trimming, SRT generation, editor audio items) reads per-cena durations directly from `tts.cenas[i].duration`, eliminating the char-offset approximation fallback.
**Depends on**: Phase 22
**Requirements**: TIMING-01, TIMING-02, TIMING-03, TIMING-04, TIMING-05
**Success Criteria** (what must be TRUE):
  1. Running `/reels/{jobId}/step/clips` on a job with Kie.ai per-cena clips trims each clip using `tts.cenas[i].duration` as the target duration, not a char-offset approximation (verifiable by diffing clip durations against audio durations — should match within a frame)
  2. The generated SRT file has cue timestamps that match the per-cena audio boundaries exactly (cena `i` starts at `sum(cenas[0..i-1].duration)` rounded to 3 decimals)
  3. The editor loads with `step_state.editor.audioItems[0].total_duration` equal to the sum of per-cena durations, and `ReelComposition.tsx` waveform remains aligned across all cenas (Bug 7 fix preserved)
  4. After cena 3+, no cumulative float drift is visible in the timeline cursor (ref doc section 9 — "Cenas desalinhadas após a terceira") because cursor is rounded to milliseconds at each step
  5. The legacy `align_srt_with_script` char-offset method is no longer called in the new per-cena code path (grep confirms dead-code removal or feature-flag guard)
**Plans**: TBD

### Phase 24: Script Schema v2
**Goal**: Roteiros generated by the LLM (regular and bible) include structured per-cena fields (`image_prompt`, `mood`, `transition_in/out`) and a top-level `character_card`, with a compatibility layer for legacy roteiros.
**Depends on**: Nothing structurally (can run in parallel with Phase 22/23, but sequenced after for safer migration)
**Requirements**: SCRIPT-01, SCRIPT-02, SCRIPT-03, SCRIPT-04, SCRIPT-05, SCRIPT-06
**Success Criteria** (what must be TRUE):
  1. Running `/reels/{jobId}/step/script` on a new job produces a roteiro JSON that validates against the v2 schema — every cena has `image_prompt` (English, 4-layer), `mood` (one of 7 enum values), `transition_in`, `transition_out`, and the top-level `character_card` is present when the tenant has a recurring character
  2. Running the same step on a biblical job produces a roteiro respecting the same v2 schema (bible system prompt updated)
  3. Loading a legacy job (roteiro without v2 fields) through `/reels/{jobId}` does not crash — missing fields are filled with defaults (`mood=calm`, `transition_in/out=fade`, `image_prompt` derived from `legenda_overlay`), verifiable by loading a pre-v4.0 job and advancing it through images + clips
  4. The `image_prompt` field is distinct from `legenda_overlay` in every v2 roteiro (no accidental reuse), and `legenda_overlay` remains PT-BR while `image_prompt` is in English
**Plans**: TBD

### Phase 25: Structured Image Generation
**Goal**: Per-cena image generation consumes `cena.image_prompt` as the primary prompt, prepends `character_card.style_seed` when present, keeps `BIBLE_STYLE_DNA` as a combinable layer (not an override), and always specifies aspect ratio explicitly.
**Depends on**: Phase 24 (needs `image_prompt`, `character_card` fields on the script)
**Requirements**: IMAGE-01, IMAGE-02, IMAGE-03, IMAGE-04
**Success Criteria** (what must be TRUE):
  1. Running `/reels/{jobId}/step/images` on a v2 job sends `cena.image_prompt` (not `narracao + legenda_overlay`) as the primary prompt to Gemini Image — verifiable by inspecting the request payload logged by the pipeline
  2. When the roteiro has a `character_card`, the `style_seed` is prepended to every per-cena prompt (visual continuity across images observable by running the step on a 5-cena job with a character and comparing the 5 outputs)
  3. A biblical job ships both `BIBLE_STYLE_DNA` AND the per-cena `image_prompt` in the final prompt (not one overriding the other) — verifiable by grepping the outgoing prompt for both substrings
  4. The final prompt always contains an explicit aspect ratio string (`9:16`, `16:9`, etc.) matching the job config, and Gemini never receives an ambiguous prompt
  5. UI hint: yes — this phase touches the reels UI only indirectly (generated images render in existing components); no new UI surfaces
**Plans**: TBD

### Phase 26: Mood-Driven Ken Burns
**Goal**: Ken Burns motion is driven by each cena's `mood` field, applied consistently in both the static slideshow path (`build_reel_video`) and the Kie.ai clips path (`concat_clips_with_audio`), gated by real per-cena duration > 6s.
**Depends on**: Phase 22 (real per-cena durations for the > 6s gate), Phase 24 (mood field)
**Requirements**: MOTION-01, MOTION-02, MOTION-03, MOTION-04, MOTION-05
**Success Criteria** (what must be TRUE):
  1. A reel with mixed moods (e.g., `mysterious`, `dramatic`, `hopeful`) renders with different Ken Burns presets per cena — verifiable by inspecting the final MP4 with a frame-by-frame scrub showing zoom-in on `mysterious`, diagonal on `dramatic`, zoom-out on `hopeful`
  2. A reel generated via economic mode / Kie.ai clips (`concat_clips_with_audio` path) has Ken Burns applied to its static images too (not just slideshow mode) — regression fix
  3. A cena with `tts.cenas[i].duration <= 6.0` renders without any Ken Burns effect (the > 6s rule from ref doc section 6.3 is honored using real durations, not estimates)
  4. Setting `REELS_KENBURNS_EASING=linear` in env changes the motion curve on the next render, and `ease-in-out` is the default when the env var is unset
  5. The even/odd alternation pattern in `video_builder.py:218-228` is no longer the motion driver (grep confirms it is removed or unreachable)
